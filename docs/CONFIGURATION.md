# Настройка анкеты

Конфигурация хранится в Google Таблице, связанной с проектом Apps Script. Сначала выполните инициализацию из [README](../README.md). Не переименовывайте листы и заголовки; добавляйте и редактируйте строки под ними. Для JSON используйте обычные двойные кавычки, без комментариев и завершающих запятых.

Инициализация создаёт недостающие листы и заполняет примером только пустые листы. Повторный запуск сохраняет существующие строки. Он также сохраняет ID связанной таблицы в свойстве скрипта `SPREADSHEET_ID`; это служебная настройка, её не нужно добавлять в `Settings` или передавать в браузер.

## Общие правила

- `id` вопроса и раздела, а также `list_id` справочника — стабильные идентификаторы. Для вопросов и разделов используйте от 1 до 64 символов: латинская буква в начале, затем латинские буквы, цифры, `_` или `-`, например `profile` или `experience_2`. Имена `constructor`, `prototype`, `__proto__` зарезервированы.
- ID вопросов должны быть уникальными. Условие может ссылаться только на вопрос, расположенный раньше в порядке анкеты.
- `position` задаёт порядок. Для удобства используйте числа с промежутками: `10`, `20`, `30`.
- Логические поля заполняйте `TRUE` или `FALSE`; для `required` и `enabled` удобно использовать флажки Google Таблиц.
- Отключение вопроса или раздела позволяет скрыть его без удаления строки. Не переиспользуйте старые ID для вопросов с другим смыслом: по ID формируются колонки ответов.
- Перед публикацией запускайте проверку конфигурации через меню таблицы и проверяйте пользовательский сценарий пробной отправкой.

Форма должна содержать хотя бы один включённый раздел и от 1 до 100 включённых вопросов. Для вопроса с выбором допустимо до 1000 уникальных вариантов; сохраняемое значение варианта — до 500 символов.

## `Settings`

Колонки: `key`, `value`, `description`. Для каждого ключа используйте одну строку. `description` — пояснение для администратора.

| `key` | Значение `value` |
| --- | --- |
| `form_title` | Заголовок анкеты |
| `form_description` | Вводный текст, например цель опроса и условия обработки ответов |
| `confirmation_message` | Сообщение после успешной отправки |
| `accept_responses` | `TRUE` — принимать ответы; `FALSE` — закрыть анкету |
| `collect_email` | `TRUE` — показывать поле email респондента |
| `email_required` | `TRUE` — сделать поле email обязательным; требует `collect_email = TRUE` |
| `submit_label` | Текст кнопки отправки |
| `closed_message` | Сообщение при закрытом приёме ответов |
| `max_responses` | Максимальное число ответов; `0` означает отсутствие заданного лимита |

Email, введённый респондентом, не проверяет его личность. Для ограничения круга участников используйте доступ к развёртыванию Google, а не только поле email.

## `Sections`

Колонки: `id`, `title`, `description`, `position`, `enabled`.

| Колонка | Назначение |
| --- | --- |
| `id` | Уникальный ID раздела, например `profile` |
| `title` | Заголовок раздела |
| `description` | Пояснение к разделу |
| `position` | Порядок раздела |
| `enabled` | Включён ли раздел |

Вопросы связываются с разделом через `Questions.section_id`.

## `Questions`

Колонки: `id`, `section_id`, `title`, `description`, `type`, `required`, `options_source`, `options_json`, `visible_if_json`, `validation_json`, `position`, `enabled`.

| Колонка | Назначение |
| --- | --- |
| `id` | Уникальный стабильный ID вопроса |
| `section_id` | ID раздела из `Sections` |
| `title` | Текст вопроса |
| `description` | Подсказка респонденту |
| `type` | Тип из таблицы ниже |
| `required` | Обязателен ли ответ, когда вопрос видим |
| `options_source` | Ссылка на справочник: `list:<list_id>` |
| `options_json` | Варианты непосредственно в строке вопроса; используйте вместо `options_source` |
| `visible_if_json` | Условие показа; пустая ячейка — показывать без условия |
| `validation_json` | Ограничения ответа; пустая ячейка — стандартные проверки типа |
| `position` | Порядок вопроса в разделе |
| `enabled` | Включён ли вопрос |

### Типы вопросов

| `type` | Ответ |
| --- | --- |
| `text` | Одна строка текста |
| `paragraph` | Многострочный текст |
| `email` | Email-адрес |
| `number` | Число |
| `date` | Дата |
| `select` | Один вариант из выпадающего списка |
| `multiselect` | Несколько вариантов |
| `radio` | Один вариант, отображённый переключателями |
| `checkbox` | Логический флажок, например согласие; обязательный флажок нужно отметить |
| `scale` | Целое значение шкалы; по умолчанию от `1` до `5` |

Для `select`, `multiselect` и `radio` задайте варианты через `options_source` или `options_json`. `checkbox` — одиночный логический ответ, а не список вариантов.

### Варианты ответов

В `options_json` допускается массив строк:

```json
["Да", "Нет", "Пока не знаю"]
```

Или массив объектов, если нужно разделить сохраняемое значение и подпись:

```json
[
  {"value": "remote", "label": "Удалённо"},
  {"value": "office", "label": "В офисе"}
]
```

В условиях и ответах используется `value`. Сохраняйте значения стабильными, даже если меняете `label`.

Чтобы переиспользовать варианты из листа `Lists`, укажите, например, `list:work_formats` в `options_source`, а `options_json` оставьте пустым.

### Условная видимость

В `visible_if_json` задаётся одно условие по предыдущему вопросу:

```json
{"question": "work_format", "operator": "equals", "value": "office"}
```

Пример для нескольких выбранных вариантов:

```json
{"question": "interests", "operator": "includes", "value": "training"}
```

| `operator` | Когда показывать вопрос |
| --- | --- |
| `equals` | Ответ равен `value` |
| `not_equals` | Ответ не равен `value` |
| `includes` | Ответ содержит `value`, например выбранный вариант в массиве |
| `not_empty` | Предыдущий вопрос заполнен |
| `empty` | Предыдущий вопрос не заполнен |

Для `not_empty` и `empty` значение `value` не требуется. Пустым считается в том числе неотмеченный флажок. `equals`, `not_equals` и `includes` не выполняются для пустого ответа. При сравнении учитывается тип значения: для текстового ответа используйте `"office"`, для числового — `5`, для флажка — `true`.

Ссылаться можно только на более ранний вопрос: циклы и условия по будущим вопросам недопустимы. Скрытый вопрос не блокирует отправку из-за `required`, его ранее введённый ответ не сохраняется и не включает зависимые вопросы.

### Проверки ответа

В `validation_json` используется объект с нужными ограничениями:

```json
{"min": 18, "max": 100}
```

```json
{"minLength": 10, "maxLength": 1000}
```

```json
{"pattern": "^[А-Яа-яЁё -]+$", "patternMessage": "Используйте русские буквы, пробелы и дефис"}
```

| Поле | Назначение |
| --- | --- |
| `min`, `max` | Нижняя и верхняя границы для числа или шкалы; минимальное и максимальное число выбранных вариантов для `multiselect` |
| `minLength`, `maxLength` | Минимальная и максимальная длина текста |
| `pattern` | Регулярное выражение для проверки текста, без внешних `/` |
| `patternMessage` | Понятное пользователю пояснение при несовпадении с выражением |

Шкала принимает только целые числа и может содержать не более 21 значения. Для собственной шкалы задайте обе границы, например `{"min": 0, "max": 10}`. Текстовые ответы ограничены 10 000 символов; `minLength` и `maxLength` должны быть целыми числами от 0 до 10 000. Длина `pattern` — до 300 символов.

Не добавляйте ограничения неподходящего типа. Сервер повторно проверяет ответы и допустимость выбранных вариантов при отправке.

## `Lists`

Колонки: `list_id`, `value`, `label`, `position`, `enabled`.

Каждая строка — один вариант. Строки с одинаковым `list_id` образуют один справочник:

| `list_id` | `value` | `label` | `position` | `enabled` |
| --- | --- | --- | --- | --- |
| `work_formats` | `remote` | Удалённо | `10` | `TRUE` |
| `work_formats` | `office` | В офисе | `20` | `TRUE` |

Вопрос с `options_source = list:work_formats` использует эти строки. `value` должно быть уникальным внутри одного справочника; `label` можно менять для отображения. Отключённые варианты не предлагаются для новых ответов.

## `Responses`

Лист заполняет приложение. Начальные служебные колонки:

| Колонка | Назначение |
| --- | --- |
| `submission_id` | Уникальный ID запроса для защиты от повторной отправки |
| `submitted_at` | Время принятия ответа |
| `respondent_email` | Введённый респондентом email, если сбор включён |
| `q:<id>` | Ответ на вопрос с соответствующим ID |

Одиночные ответы сохраняются как скалярные значения, несколько вариантов — как JSON-массив. Для анализа массива понадобится разбор JSON. Не переименовывайте служебные колонки и `q:<id>`: они связывают новые ответы с правильными вопросами. Перед ручными массовыми операциями сделайте копию таблицы.

При записи ответы защищаются от интерпретации как формулы Google Таблиц. Отправка выполняется с блокировкой, а повтор одного `submission_id` обрабатывается как тот же запрос. Это защита от случайного повтора, а не подтверждение личности и не ограничение «один человек — один ответ».

## Проверка перед рассылкой

1. Выполните проверку конфигурации из меню таблицы.
2. Откройте опубликованный адрес `/exec` с тем уровнем доступа, который будет у респондентов.
3. Проверьте обязательные поля, все используемые типы и появление условных вопросов.
4. Отправьте пробный ответ и убедитесь, что `Responses` содержит ожидаемые значения.
5. Проверьте сообщение об успехе и поведение при `accept_responses = FALSE`, затем верните нужную настройку.
6. Удалите только свои пробные строки, если они не должны входить в результаты.

Локальные Node.js-тесты не проверяют права Google, ограничения организации или доступность опубликованного приложения. Учитывайте квоты Google Apps Script при выборе нагрузки и сценария использования.


## Обязательное ФИО (новая версия)

ФИО добавляется приложением автоматически первым вопросом с ID `respondent_fio`. Этот ID нельзя использовать в `Questions`. Источник — настройка `fio_range` листа `Settings`, по умолчанию `People!A2:A`. Лист `People` создаётся функцией `setupForm`; первая строка — заголовок, далее реальные ФИО. Для других листов укажите, например, `'Сотрудники'!B2:B500`. Диапазон должен состоять из одного столбца, до 10 000 строк. Пустые и повторные значения удаляются из выдачи. Список обновляется при загрузке страницы формы и проверяется заново при отправке. Пустой список блокирует отправку обязательного ФИО.

Список ФИО передаётся браузеру участника для поиска; доступ к форме должен соответствовать допустимой аудитории этого списка. Выбор имени не является аутентификацией. Ответ хранится в `Responses` в столбце `q:respondent_fio`.

## Тип вопроса `map`

Окно с картой OpenStreetMap, отметкой точки, масштабом и перемещением. Можно выбрать центр клавишей Enter и перемещаться стрелками. Координаты допускается ввести вручную, в том числе если подложка не загрузилась. Широта: от −90 до 90, долгота: от −180 до 180. Сервер принимает только конечные числа и сохраняет JSON `{"lat":55.75,"lng":37.61}` в столбце `q:<id>`. `required`, условная видимость и порядок действуют как для других вопросов. Варианты ответа не нужны; проверки координат встроены. Подложка использует внешний сервис `tile.openstreetmap.org` на стороне браузера; Google API-ключ не нужен. Поиск адресов и автоматическое определение местоположения не предусмотрены.
