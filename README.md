# Анкеты из Google Таблиц

Веб-форма на Google Apps Script: структуру анкеты и варианты ответов вы редактируете в Google Таблице, а ответы записываются в отдельный лист этой же таблицы. В репозитории находятся исходники приложения; публикация выполняется в вашей учётной записи Google.

## Возможности

- Первое обязательное поле — ФИО из отдельного листа, выбор в окне с поиском.
- Отметка на карте OpenStreetMap с сохранением координат.

- Разделы и вопросы с сортировкой, обязательными полями и пояснениями.
- Текст, длинный текст, email, число, дата, список, несколько вариантов, переключатели, флажок согласия и шкала.
- Варианты из общего справочника или JSON в строке вопроса.
- Условная видимость по ответам на предыдущие вопросы.
- Проверка ответов на сервере, защита от формул в ячейках и повторной отправки одного запроса.
- Блокировка параллельной записи при одновременных отправках.

Вход через Google для респондентов зависит от выбранного доступа при публикации. Введённый в форме email является сообщённым пользователем адресом и не подтверждает его личность. Загрузка файлов и автоматический подсчёт баллов пока не реализованы.

## Установка

1. Создайте Google Таблицу или выберите существующую. Не открывайте её для общего редактирования: респондентам нужна ссылка на веб-приложение, а не на таблицу.
2. Откройте **Расширения → Apps Script**.
3. Добавьте четыре файла типа «Скрипт»: `Code.gs`, `Domain.gs`, `SheetStore.gs`, `Admin.gs`. Замените их содержимое одноимёнными файлами из этого репозитория.
4. Добавьте файл типа **HTML** с именем `Index` и скопируйте в него `Index.html`.
5. В настройках проекта включите показ файла манифеста `appsscript.json` в редакторе. Скопируйте в него содержимое `appsscript.json` из репозитория и сохраните проект.
6. В редакторе выберите функцию `setupForm` и запустите её. Подтвердите запрашиваемые Google разрешения только для своего проекта. Инициализация запоминает ID связанной таблицы в свойствах скрипта, создаёт недостающие листы и заполняет пустые листы примером анкеты. Существующие строки сохраняются.
7. Перезагрузите таблицу. Через появившееся меню «Расширенная форма» можно повторить инициализацию и проверить конфигурацию.

Служебные функции с завершающим `_` предназначены для редактора и меню таблицы; через `google.script.run` они недоступны.

## Публикация формы

1. В Apps Script откройте **Развернуть → Новое развертывание**, выберите тип **Веб-приложение**.
2. Для выполнения выберите **от своего имени**. Так приложение записывает ответы в закрытую таблицу с правами владельца.
3. Осознанно выберите, кому разрешён доступ. Публичный доступ подходит только для публичной анкеты и доступен, если это разрешает политика вашего Google-аккаунта или организации. Ограничение доступа через Google и ссылка на публичную форму — разные механизмы.
4. Разверните приложение и используйте выданную ссылку с окончанием `/exec`. Адрес `/dev` предназначен для разработки и не подходит для рассылки респондентам.
5. После изменения исходников сохраните их и обновите существующее развёртывание на новую версию через **Управление развертываниями**. Изменение строк конфигурации в таблице не требует переноса исходников.

Публикация не выполняется автоматически из Git. Для начальной установки не нужны `clasp`, npm-зависимости или передача Google-учётных данных в этот репозиторий. При необходимости синхронизацию через `clasp` можно настроить отдельно.

## Настройка анкеты

После инициализации появятся листы:

| Лист | Назначение |
| --- | --- |
| `Settings` | Название, описания, приём ответов и общие настройки |
| `Sections` | Разделы анкеты |
| `Questions` | Вопросы, типы, проверки и условия показа |
| `Lists` | Общие справочники вариантов |
| `People` | Список ФИО: столбец A, начиная со строки 2 |
| `Responses` | Отправленные ответы; заполняется приложением |

Схема колонок, значения настроек и примеры JSON описаны в [docs/CONFIGURATION.md](docs/CONFIGURATION.md). Сохраняйте имена листов, заголовки и стабильные ID: они связывают вопросы, условия, справочники и сохранённые ответы. Перед публикацией изменённой анкеты проверьте её конфигурацию через меню таблицы и отправьте пробный ответ.

## Данные и доступ

Таблица с ответами должна оставаться доступной только её администраторам. Веб-форма не передаёт респонденту ID таблицы и не предоставляет редакторских функций. Если форма опубликована для всех, любой обладатель ссылки может открыть её и отправить ответ: ссылка сама по себе не является контролем доступа.

Собирайте только необходимые данные, укажите цель сбора и срок хранения в описании анкеты, ограничьте доступ к `Responses` и удаляйте ответы согласно вашим правилам. Если используется сохранение черновика в браузере, включайте его осознанно; удаление черновика очищает локальную копию, но не уже отправленный ответ. На общем устройстве не сохраняйте чувствительные ответы.

## Локальная проверка

Нужен установленный Node.js с поддержкой встроенного тестового раннера. В каталоге репозитория выполните:

```sh
npm test
```

Для проверки интерфейса в установленном Chromium также выполните `npm run test:browser` (Node.js 22+; путь к браузеру можно задать переменной `CHROMIUM`). Этот сценарий использует локальную имитацию сервисов Google и проверяет заполнение, условные поля, черновик и повторную отправку после сбоя связи.

Команда `npm test` использует `node --test`; установка npm-зависимостей не нужна. Локальные тесты проверяют логику, которую можно выполнить вне Google Apps Script. Они не заменяют авторизацию, публикацию и пробную отправку в вашей Google Таблице. Проверка реального развёртывания требует вашей учётной записи Google и здесь не выполнялась.

При разработке сохраняйте исходники в Git, переносите нужные файлы в редактор Apps Script и обновляйте версию веб-приложения. Не сохраняйте токены, секреты или выгрузку персональных ответов в репозитории.

## Если форма не работает

- **Нет меню в таблице:** сохраните проект и перезагрузите таблицу; проверьте, что проект открыт именно из этой таблицы.
- **Не найдена таблица:** выполните `setupForm` из связанного проекта под учётной записью с доступом к таблице.
- **Ошибка конфигурации:** проверьте заголовки, уникальность ID и JSON по [справочнику](docs/CONFIGURATION.md), затем запустите проверку через меню.
- **Открывается старая версия интерфейса:** обновите версию развёртывания и откройте ссылку `/exec`.
- **Респондент не может открыть форму:** проверьте настройки доступа развёртывания и ограничения Google Workspace.
- **Ответ отклонён:** убедитесь, что приём включён, лимит ответов не исчерпан и обязательные видимые поля заполнены. Квоты и временные ограничения Google Apps Script также могут влиять на отправку.

## Отправка кода через clasp

Для подготовленного проекта Apps Script ID:

```text
1gsgf_2QY1oa8Vt2nlPbjkKRovPQQyAHtsqjjX-ABtHAIbLbQVvFGb26c
```

В облачной рабочей копии уже создан локальный `.clasp.json`; он исключён из Git. После клонирования скопируйте `.clasp.example.json` в `.clasp.json` (это можно сделать в файловом менеджере). Пример уже содержит ID нужного проекта. Содержимое конфигурации:

```json
{
  "scriptId": "1gsgf_2QY1oa8Vt2nlPbjkKRovPQQyAHtsqjjX-ABtHAIbLbQVvFGb26c",
  "rootDir": "."
}
```

На своём компьютере сначала получите исходники:

```sh
git clone https://github.com/sergeraylenyaru/Opros.git
cd Opros
```

Скопируйте `.clasp.example.json` в `.clasp.json`. Затем из этой папки выполните:

```sh
npx @google/clasp@3.4.1 login
npx @google/clasp@3.4.1 show-file-status
npx @google/clasp@3.4.1 push
```

Нужен Google-аккаунт с правом редактирования этого проекта. В [настройках Apps Script](https://script.google.com/home/usersettings) включите Google Apps Script API, если он выключен. Перед первой загрузкой сохраните существующие исходники целевого проекта: `push` заменяет содержимое проекта. Для резервной копии можно выполнить `clasp clone ID` в отдельном пустом каталоге; не выполняйте `pull` в каталоге этой разработки.

`.claspignore` разрешает загрузку только шести файлов приложения. Проверьте этот список перед `push`. Не передавайте OAuth-коды, токены и файл `.clasprc.json` в чат или Git. Загрузка кода не публикует веб-приложение и не создаёт листы: после неё выполните инициализацию и развёртывание по инструкции выше.


## Обязательное ФИО и отметка на карте

ФИО всегда стоит первым и обязательно для отправки. Оно добавляется автоматически: создавать строку для него на листе `Questions` не нужно. ID `respondent_fio` зарезервирован. При нажатии «Выбрать ФИО» открывается окно с поиском по любой части фамилии, имени или отчества. Поиск не различает регистр и е/ё. Произвольный ввод вместо выбора не допускается.

После обновления кода запустите `setupForm`: появится лист `People` с заголовком «ФИО». Вставьте реальные ФИО по одному в ячейки `A2`, `A3` и далее. Примерные фамилии приложение не добавляет. Если на `Questions` остался старый пример «Как вас зовут?», поставьте в его строке `enabled = FALSE`, чтобы не спрашивать имя повторно.

В `Settings` настройка `fio_range` задаёт диапазон: по умолчанию `People!A2:A`, другой пример — `'Сотрудники'!B2:B500`. Поддерживается один столбец, до 10 000 строк. Пустые строки и одинаковые ФИО пропускаются. Для различения полных тёзок добавьте к значениям согласованный идентификатор, например отдел. Существующие вопросы и ответы при повторной инициализации сохраняются. Выбор ФИО не подтверждает личность; список доступен тем, кому открыта анкета.

Для вопроса «Отметка на карте» создайте строку в `Questions`:

| id | section_id | title | type | required | position | enabled |
| --- | --- | --- | --- | --- | --- | --- |
| location | details | Отметьте место | map | TRUE | 20 | TRUE |

В `section_id` укажите ID существующего включённого раздела. `options_source`, `options_json`, `validation_json` оставьте пустыми. Карту можно перемещать перетаскиванием, масштабировать кнопками и щелчком ставить точку; доступны клавиатура и ручной ввод координат. Подложка загружается с `tile.openstreetmap.org` без API-ключа; подключение к Интернету требуется на устройстве участника. Если подложка недоступна, координаты можно ввести вручную. В `Responses` значение сохраняется в столбце `q:location` как JSON, например `{"lat":55.75,"lng":37.61}`. Адрес по координатам автоматически не определяется.

Обновление установленного приложения:

1. Скачайте свежую версию с GitHub (или выполните `git pull`, если клонировали репозиторий). Сохраните свой `.clasp.json`.
2. Выполните `npx.cmd @google/clasp@3.4.1 push` в PowerShell.
3. В редакторе Apps Script выберите `setupForm` и нажмите «Выполнить». Ручную обёртку добавлять больше не нужно — она включена в исходники.
4. Заполните лист `People` и настройте вопросы.
5. В «Развернуть → Управление развёртываниями» измените используемое развёртывание: выберите новую версию и сохраните. Ссылка `/exec` останется прежней.


## Вход администратора и редактор вопросов

На странице анкеты есть кнопка **«Вход администратора»**. Она доступна и когда приём ответов закрыт или в конфигурации обнаружена ошибка.

Первый запуск после обновления:

1. Загрузите актуальные исходники через `clasp push`. В списке должны быть **6 файлов**, включая `Admin.gs`.
2. Откройте Google Таблицу и её редактор Apps Script. В списке функций выберите **`setupAdmin`** и нажмите «Выполнить». Либо перезагрузите таблицу и выберите «Расширенная форма → Создать / сменить пароль администратора».
3. Подтвердите создание пароля. Сгенерированный пароль будет показан в окне Google Таблицы. Скопируйте его в менеджер паролей. Не добавляйте пароль в код, листы таблицы или Git.
4. Обновите веб-развёртывание на новую версию. Откройте форму, нажмите «Вход администратора» и введите пароль.

Редактор позволяет менять название и описание анкеты, открывать/закрывать приём ответов, задавать сбор email и диапазон ФИО, создавать и редактировать разделы, добавлять, удалять, включать/выключать и переставлять вопросы. Для каждого вопроса доступны тип, обязательность, варианты, источник вариантов из `Lists`, условия показа и ограничения ответа. Для собственных вариантов используйте одну строку на вариант; формат `код | подпись` позволяет сохранить стабильные коды.

Изменения применяются кнопкой **«Сохранить изменения»** и записываются в `Settings`, `Sections`, `Questions`. Новая публикация после таких изменений не нужна: участники увидят их при следующей загрузке формы. ФИО остаётся первым обязательным полем. `People`, `Lists` и `Responses` редактор не перезаписывает. Для этих списков продолжайте использовать таблицу. Удаление вопроса сохраняет старый столбец ответов в `Responses`; ID существующих вопросов сохраняются.

Неверные настройки отклоняются до записи. Если настройки изменены в другой вкладке или вручную в таблице, редактор попросит загрузить их заново, чтобы не затереть чужие изменения. Кнопка «Обновить из таблицы» заменяет локальные несохранённые изменения после подтверждения. Поддерживаются стандартные столбцы конфигурации; дополнительные пользовательские столбцы в редактируемых листах нужно обрабатывать через таблицу.

Сессия администратора действует до 30 минут и может завершиться раньше при очистке кеша Google. Пароль и сессия не сохраняются в браузерный черновик. После работы нажмите «Выйти к форме». Если сессия истекла, выйдите и войдите заново; несохранённые изменения следует сохранить до её истечения. Ограничение входа — 10 попыток за пятиминутное окно на весь проект. Если пароль потерян, повторный запуск `setupAdmin` создаст новый и немедленно отключит все прежние сессии.

Это отдельный пароль приложения. Он не связан с вводимыми ФИО, email участника или входом в Google. Создание и смена пароля доступны из редактора/меню связанной таблицы; каждый административный запрос из веб-интерфейса проверяет серверную сессию. Все пользователи, которым вы передали этот пароль, получают одинаковые права редактора вопросов. Держите доступ к самому проекту Apps Script и таблице у доверенных администраторов.
