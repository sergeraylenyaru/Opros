# Opros — формы с настройками в Google Таблицах

Веб-приложение Google Apps Script: несколько опросов, обязательное ФИО с поиском, вопросы с вариантами и галочками, карты и списки из других Google Таблиц. Администратор работает через интерфейс; участникам отправляется отдельная ссылка на нужную форму.

## Что доступно

- Каталог форм с поиском, статусами, количеством вопросов и ответов.
- Создание форм из интерфейса. Каждая новая форма получает **два собственных листа**: `Вопросы_<id>` и `Ответы_<id>`.
- Редактор с вкладками «Вопросы», «Разделы», «Настройки»: порядок, обязательность, варианты, условия показа и проверки.
- Отдельная ссылка участникам и независимый приём ответов для каждой формы.
- Обязательное ФИО первым полем, выбор в окне с поиском из `People!A2:A` или другого настроенного диапазона.
- Текст, длинный текст, email, число, дата, выпадающий список, один/несколько вариантов, согласие, шкала, поиск по списку и отметка на карте.
- Списки из внешней таблицы: **файл + название листа + столбец + первая строка данных**, проверка источника в редакторе.
- Интерфейс для телефона и компьютера, шаги, прогресс, сообщения об ошибках, черновик по желанию участника.
- Проверки на сервере, защита от формул в ответах, блокировка параллельных записей, повтор запроса без дубликата.

## Установка и обновление

Исходники: <https://github.com/sergeraylenyaru/Opros>.

1. Откройте нужную Google Таблицу → **Расширения → Apps Script**.
2. Добавьте скрипты `Code.gs`, `Domain.gs`, `SheetStore.gs`, `Admin.gs`, `Forms.gs`, HTML-файл `Index`, манифест `appsscript.json` из репозитория. Либо используйте `clasp` по инструкции ниже.
3. В редакторе выберите **`setupForm` → Выполнить** и разрешите доступ. Будут подготовлены общие листы и реестр `Forms`. Существующие вопросы, ответы и пароль сохранятся.
4. Заполните `People`: заголовок в A1, реальные ФИО по одному в A2 и далее. Примерные фамилии приложение не добавляет.
5. Для первого входа администратора запустите **`setupAdmin`**. Переключитесь в Google Таблицу: там появится подтверждение создания пароля, затем сам пароль. Сохраните его в менеджере паролей. При обычном обновлении повторять этот шаг не нужно: он меняет пароль и завершает прежние сессии.
6. **Развернуть → Новое развёртывание → Веб-приложение**: выполнение от владельца, доступ — для выбранной аудитории. При обновлении существующего приложения выберите **Управление развёртываниями → Изменить → Новая версия**. Используйте ссылку `/exec`.
7. На странице формы нажмите **Вход администратора**. В каталоге выберите **Создать форму**, задайте название, настройте вопросы. Новая форма сначала закрыта: включите приём на вкладке «Настройки» и сохраните.
8. Нажмите **Ссылка участникам**. Ссылка содержит `?form=<id>` и ведёт именно на этот опрос. Отправьте пробный ответ и проверьте его лист ответов.

Редактирование формы через интерфейс не требует повторной публикации кода. Участник получает изменения после перезагрузки страницы. Приложение не публикуется автоматически из Git.

### Обновление через clasp в Windows

Установите Node.js 22+ и скачайте свежий ZIP исходников. Замените исходники в своей рабочей папке, включая **`.claspignore`**, сохранив `.clasp.json`. В PowerShell из этой папки:

```powershell
npx.cmd @google/clasp@3.4.1 push
```

Должно загрузиться **7 файлов**, включая `Forms.gs` и `Admin.gs`. Затем выполните `setupForm` и обновите версию веб-развёртывания. Пароль администратора сбрасывать не требуется.

Для первой установки создайте `.clasp.json` из примера:

```powershell
node -e "require('fs').copyFileSync('.clasp.example.json', '.clasp.json')"
npx.cmd @google/clasp@3.4.1 login
npx.cmd @google/clasp@3.4.1 show-file-status
npx.cmd @google/clasp@3.4.1 push
```

Пример привязан к проекту `1gsgf_2QY1oa8Vt2nlPbjkKRovPQQyAHtsqjjX-ABtHAIbLbQVvFGb26c`. Для своего проекта замените scriptId. Аккаунту нужны права редактора проекта; включите Apps Script API в <https://script.google.com/home/usersettings>. Перед первой отправкой сохраните исходники целевого проекта: push заменяет его код. Не выполняйте pull в папке этой разработки. На macOS/Linux можно использовать `npx` вместо `npx.cmd`.

## Несколько форм и хранение данных

Общий лист `Forms` хранит соответствие ID форм и их двух листов. Не меняйте ID и имена листов вручную. В листе `Вопросы_<id>` хранятся строки типов `settings`, `sections`, `questions`; поэтому для новой формы не нужны дополнительные листы разделов или настроек. Редактируйте их через интерфейс.

`People` и `Lists` — общие справочники. Диапазон ФИО можно менять отдельно для каждой формы через настройку `fio_range`, например `'Сотрудники'!B2:B500`. ФИО обязательно во всех формах. Для полных тёзок используйте различимые значения, например добавьте отдел. Выбор ФИО не подтверждает личность.

**Совместимость:** прежняя форма доступна как `default`, со старыми листами `Settings`, `Sections`, `Questions`, `Responses`. Старые листы не переносятся и не удаляются. Ранее отправленная ссылка без параметров по-прежнему открывает эту форму. Изменение одной формы не меняет вопросы, ответы и браузерные черновики остальных. Число форм ограничивается квотами и размером Google Таблиц, а не фиксированным числом в приложении.

## Список из другой Google Таблицы

1. В вопросе выберите тип **Поиск по списку**, **Выпадающий список**, **Один вариант** или **Несколько вариантов**.
2. В поле «Источник вариантов» выберите **Из другой Google Таблицы**.
3. Укажите ссылку на файл или ID, точное название листа, букву столбца (например `A` или `BC`) и первую строку данных (обычно `2`, если в первой заголовок).
4. Нажмите **Проверить источник**. Редактор покажет число вариантов и первые значения.
5. Сохраните форму.

Файл должен быть доступен **Google-аккаунту владельца веб-приложения**. Открывать файл всем в Интернете не требуется. Пустые строки и повторы пропускаются; используются отображаемые значения ячеек. Поддерживается до 10 000 читаемых строк и до 1 000 уникальных вариантов вопроса. Источник перечитывается при открытии и отправке формы; удалённый из справочника ответ может быть отклонён при отправке. Список вариантов доступен участникам формы; выбирайте данные под её аудиторию. Исходные файлы не редактируются.

Для ручных вариантов — одна строка на ответ; `код | подпись` позволяет сохранять стабильные коды. Старые справочники `Lists` тоже поддерживаются.

## Карта

Тип **Отметка на карте**: щелчок ставит точку, перетаскивание перемещает карту, кнопки меняют масштаб. Стрелки и Enter работают с клавиатуры. При недоступной подложке можно ввести координаты вручную. Координаты сохраняются текстом `55.75, 37.61` в столбце `q:<id>`. Подложка OpenStreetMap загружается браузером с `tile.openstreetmap.org`; API-ключ не требуется. Поиск адреса и определение примерного адреса точки доступны в текущей карте без ключа через OpenStreetMap/Nominatim.

## Администратор и данные

Веб-запросы редактирования требуют серверной сессии. Сессия действует до 30 минут, пароль хранится только как хеш в свойствах скрипта. Для смены/восстановления пароля запустите `setupAdmin`: все старые сессии перестанут работать. Ограничение входа — 10 попыток за пятиминутное окно на весь проект. Не передавайте пароль, OAuth-коды и `.clasprc.json` в чат или Git.

Редактор проверяет настройки перед записью и отклоняет сохранение устаревшей версии. Удаление вопроса не удаляет его прежние ответы. ФИО, email и ответы собираются с правами владельца; держите таблицу закрытой от респондентов и ограничивайте доступ к веб-приложению под свою аудиторию. Email указывает сам участник. Черновики хранятся в браузере только по согласию; не включайте их на общем устройстве.

## Проверка разработки

```sh
npm test
npm run test:browser
```

Зависимости приложения не требуются. Первый запуск использует встроенный Node test runner. Браузерный сценарий требует установленный Chromium (путь можно задать через `CHROMIUM`), проверяет заполнение, карту, черновики, повторную отправку, вход администратора, редактор, создание формы и внешний справочник. `SMOKE_MOBILE=1` включает мобильную проверку. Используются локальные имитации сервисов Google, а не реальное развёртывание. Для итоговой проверки отправьте ответ в установленное приложение своей учётной записи Google.

Подробности старой табличной схемы и новых источников: [docs/CONFIGURATION.md](docs/CONFIGURATION.md).

## Единый первый запуск и восстановление после ошибки настройки

В редакторе откройте **Code.gs**, выберите **startApp** и нажмите «Выполнить». Функция создаёт недостающую структуру, сохраняет привязку к таблице и, если пароль ещё не задан, предлагает создать пароль администратора. При повторном запуске существующие вопросы, ответы и пароль сохраняются. Окна подтверждения и пароля появляются в Google Таблице — переключитесь на её вкладку.

`setupForm` также остаётся доступной для подготовки только структуры; `setupAdmin` теперь находится в том же файле `Code.gs`. Её реализация требует загруженный `Admin.gs`. Ошибка условия вопроса больше не блокирует создание структуры и привязку: через кнопку администратора можно исправить вопросы или создать другую форму. Проверка условий по-прежнему выполняется при сохранении и заполнении — ошибочная анкета не считается исправленной автоматически.

Сообщение «Условие должно ссылаться на предыдущий вопрос: team_size» означает, что вопрос `role` отсутствует, выключен либо расположен после `team_size`. В старом листе `Questions` проверьте строку с `id=role`: включите её и поставьте `position` меньше, чем у `team_size`, в предыдущем или том же разделе. Если условие не нужно, очистите ячейку `visible_if_json` строки `team_size`. Не удаляйте листы с полученными ответами.

### Если SpreadsheetApp.getUi недоступен

Создание структуры теперь не требует окон Google Таблицы. Если старт не может показать пароль в окне:

1. В PowerShell на своём компьютере создайте случайный ключ командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` и сохраните результат в менеджере паролей. Это пароль администратора; не отправляйте его в чат.
2. Apps Script → Настройки проекта → Свойства скрипта → Добавить свойство: имя `ADMIN_SETUP_KEY`, значение — ваш ключ (64 символа). Сохраните.
3. Запустите `startApp`. Ключ будет преобразован в хеш, свойство `ADMIN_SETUP_KEY` автоматически удалится. Ключ не выводится в журнал.
4. Для входа на странице приложения используйте сохранённый ключ. После обновления кода обновите версию веб-развёртывания.

Способ подходит и для повторной настройки пароля, когда окна таблицы недоступны. Для выполнения настройки по-прежнему нужен контекст связанной таблицы; публичная веб-форма не принимает ключ настройки и не создаёт администратора по запросу участника.

## Яндекс Карты и удобный выбор точки

В редакторе формы на вкладке **Настройки** теперь есть поле **«Карта для отметки координат»**:

- **OpenStreetMap — без ключа:** увеличенное окно, плавное перемещение во время перетаскивания, масштабирование колесом под курсором, двойным щелчком и жестом двумя пальцами. На карте остаётся метка; координаты можно ввести вручную. Исправлен прежний сдвиг долготы при выборе точки.
- **Яндекс Карты — с API-ключом:** встроенная карта с поиском адреса, перетаскиваемой меткой, масштабированием, стандартными элементами управления и кнопкой «Отметить центр карты». Результат поиска можно уточнить перемещением метки. Выбор фиксируется только кнопкой «Использовать точку»; закрытие окна не сохраняет изменения.

Для подключения Яндекса:

1. В [кабинете разработчика Яндекс Карт](https://developer.tech.yandex.ru/) получите браузерный ключ для **JavaScript API 2.1** и проверьте условия использования/тариф сервиса. Документация: <https://yandex.ru/dev/jsapi-v2-1/doc/ru/>.
2. Выберите Яндекс Карты в настройках нужной формы и вставьте ключ в **«Браузерный API-ключ Яндекс Карт»**. Сохраните форму.
3. Настройте разрешённые домены ключа для реального развёрнутого приложения. Google Apps Script показывает форму в iframe на `googleusercontent.com`, что нужно учитывать в ограничениях HTTP Referer. Уточняйте фактический адрес iframe и рекомендации Яндекса; не снимайте ограничения ключа ради устранения ошибки.
4. Обновите страницу формы и проверьте поиск, отметку и отправку ответа. Ключ загружается браузером с `api-maps.yandex.ru`; он публичный по назначению. Не вставляйте сюда пароль администратора или серверные секреты.

В табличных настройках используются `map_provider` (`osm` или `yandex`) и `yandex_maps_key`. Поля можно задать отдельно для каждой формы. Без ключа используется простая карта. При ошибке загрузки Яндекса доступны ручные координаты и кнопка перехода к простой карте. Новые координаты сохраняются текстом: `55.75, 37.61`. При выборе ключа/провайдера после уже открытой карты перезагрузите страницу, чтобы применить настройки SDK.

В локальных браузерных проверках используйте `SMOKE_YANDEX=success npm run test:browser` для имитации клика, поиска адреса и перетаскивания метки, `SMOKE_YANDEX=failure npm run test:browser` — для ошибки загрузки и запасной карты. Эти сценарии используют тестовый адаптер и не доказывают работоспособность настоящего ключа, тарифа или сетевого доступа к Яндексу. Реальный ключ в эту облачную среду не предоставлялся.

### Координаты и примерный адрес в ответах

Новые ответы на вопрос с картой теперь записываются в `q:<id>` как обычный текст, например `55.804668, 38.983412` (сначала широта, затем долгота). Старые JSON-ответы не переписываются. Для каждого вопроса с картой автоматически добавляется отдельный столбец `q:<id>:address` с примерным адресом, если его удалось получить.

В режиме **Яндекс Карты** над картой есть отдельный поиск: введите город, улицу и дом, нажмите «Найти адрес», выберите результат. При щелчке по карте или перемещении метки приложение запрашивает примерный адрес через геокодер Яндекса. Адрес показывается до подтверждения. Координаты можно сохранить и без адреса, если сервис недоступен или не нашёл место. Адрес является подсказкой, не подтверждает точность точки и передаётся из браузера вместе с ответом.

Для этих функций выберите Яндекс Карты в настройках формы и укажите браузерный ключ JavaScript API 2.1 с доступом к геокодированию. Проверьте тариф, разрешённые домены и условия хранения результатов геокодирования у Яндекса. В простой карте без ключа поиск и определение адреса выполняются через OpenStreetMap/Nominatim. Реальная работа геокодера проверяется владельцем после подключения ключа; локальные тесты используют имитацию Яндекс API.


### Адреса на текущей карте без ключа (рекомендуемый режим)

Используйте **OpenStreetMap — без ключа** в настройках формы. Над картой есть поле «Город, улица, дом» и кнопка «Найти адрес». Выберите найденный результат, при необходимости уточните положение метки. Примерный адрес по щелчку или выбранным координатам запрашивается у Nominatim; регистрация и ключ Яндекса не нужны.

Запросы выполняются Google Apps Script, поэтому после обновления `appsscript.json` запустите `setupForm` в редакторе и подтвердите новое разрешение на внешние запросы (`script.external_request`). Затем обновите версию веб-развёртывания. Пароль администратора не меняется. Исходники по-прежнему состоят из 7 файлов для clasp push.

Ответы: `q:<id>` — строка `55.804668, 38.983412`; `q:<id>:address` — примерный адрес, если найден. Старые ячейки JSON не переписываются. Если поиск временно недоступен или результатов нет, координаты можно сохранить без адреса. Публичный Nominatim не гарантирует доступность: приложение кеширует ответы на час и ограничивает новые запросы одним примерно в секунду на проект, без автоматических запросов при каждом вводимом символе. При частых запросах интерфейс предлагает повторить поиск. Правила сервиса: <https://operations.osmfoundation.org/policies/nominatim/>. Для массового использования потребуется отдельный сервис геокодирования.

Текст адреса и координаты передаются Nominatim для поиска, ответ является приблизительным. Проверки в облачной среде используют имитацию внешнего сервиса; реальный поиск проверьте после обновления и авторизации приложения в Google.
